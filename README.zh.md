# DeepSeek Bot

[English](README.md) | 中文

![版本](https://img.shields.io/badge/版本-v0.1_预览-blue) ![DSH](https://img.shields.io/badge/DSH-0.2.0--rc.2-4D6BFE) ![许可](https://img.shields.io/badge/许可-Apache_2.0-green)

DeepSeek Bot（简称 DS Bot）是一个基于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（简称 dsh）的 bot 插件，插件将 dsh 改造为 bot 形式。你可以与自己创建的 bot 交流、工作。

![和 Chief 说一句话，它就把 bot 和群聊建好](docs/images/team.zh.png)

## 任务完成提醒

员工通过 `complete_task` 声明已验证的最终交付；本轮成功结束后，右下角出现静音提醒卡片，显示员工、任务及成果入口。普通回复、失败/停止、等待批准及成员内部协作不触发完成提醒；群聊由协调人声明最终汇总交付。这是员工明确提交的完成回执，并非系统独立判断成果质量。

团队栏铃铛保留最近 100 条交付记录和未读标记。卡片展示六秒后收起，鼠标悬停或键盘聚焦时暂停，批量完成最多显示三张卡片。打开对话沿用画布聊天窗口，不重新居中；查看文件使用经典会话的内置文件查看器。正在阅读的对话完成时静默记为已读。弹窗和可选提示音设置保存在当前浏览器配置中；后台系统通知需在通知中心主动授权，且应用及服务必须保持运行。重新打开窗口保留历史，不重复弹出旧提醒。

## 安装

先装好 dsh，并在 dsh 里配好至少一个模型。ds bot 直接使用 dsh 里的模型。

**dsh Desktop（Windows、macOS）**

1. 侧栏点 **插件** → **添加插件**。
2. **包名或地址** 填 `ds-bot`。在中国大陆，**安装源** 选 **中国大陆镜像源**。
3. 点 **安装**，再点 **立即启用**。如果提示“下次启动生效”，完全退出 dsh 再打开。

连不上 npm 时，第 2 步也可以填 [Releases](https://github.com/Fei2411/DeepSeek-Bot/releases) 里下载的 `ds-bot-0.1.5.tgz` 的完整路径，或者 `github:Fei2411/DeepSeek-Bot#v0.1.5&path:/ds-bot`（需要装 Git）。

**dsh Web（Windows、macOS、Linux）**

需要 Node.js `22.19` 以上和 pnpm。

```sh
npx @deepseek-ai/dsh@0.2.0-rc.2 plugin --profile web add ds-bot
npx @deepseek-ai/dsh@0.2.0-rc.2 web
```

## 功能

### 员工画布（尚未发布）

**Chief 是唯一的总助理**，使用普通员工的置顶联系人样式，保留原有头像和会话。一句话描述要建立的部门，Chief 通过 `create_department` 创建负责人、专职员工和独立群聊；通过 `organize_team` 将已有员工组织成团队，通过 `assign_employee` 显式转组。团队由名称、长期职责、负责人和固定成员定义；员工可以独立存在，或归属一个长期团队，同时加入多个协作群。跨团队员工可以直接沟通和派任务，负责人负责分工、进度和成果协调。打开聊天后，团队栏保留在旁边；旧版独立总助会话保留在员工目录中。打开 Chief 不调用模型，也不改变系统权限。

加群、退群和画布布局不会改变团队归属、私聊、正在执行的任务或文件权限。群聊保留原有回复模式，默认由协调者先回复，使用 `@姓名` 指定成员。员工忙碌时新任务默认排队，显式 `when: now` 用于纠正或紧急补充。负责人身份不会自动授予员工管理权限，负责人离队或删除前须先交接。旧数据只将明确建立的部门迁移为团队，普通聊天群不会自动变成团队。

浮动组件展开、收起时不改变桌面 Agent 的位置。从团队栏拖入时仅跟随头像和名称，选中 Agent 仅显示柔和高光，右键打开管理菜单。小组件向画布内侧展开，临时避让后在收起时回到保存的位置；手动拖动仍可自由重叠，点击组件可置顶。聊天统一在左侧团队栏旁的固定区域打开，仍可手动移动。

这个开发分支新增了容纳独立员工和群聊的画布。背景铺满工作区，沿用所提供 Starbots 的浅灰渐变背景、柔白半透明面板、可拖动折叠的员工列表和底部居中的头像栏；深色外观随宿主切换为石板灰。这套主题仅用于画布。点 **创建员工** 配置新的 Bot；从 **员工目录**、员工列表或头像栏打开已有员工。展开后的对话窗口可以移动和调整大小，缩小或关闭窗口仍保留员工身份、记忆和原有对话。

员工默认显示为可拖动的 120×112 头像入口，群聊保留 320×200 的摘要卡片及真实成员。点击员工头像或群聊的 **打开对话** 才加载对应聊天，手动打开的多个对话可以同时保留。刷新后保留位置和分组、恢复收起状态，不会自动加载所有历史。**整理卡片** 按实际尺寸和视觉分组紧凑排列；**收起对话** 只收起内容、保留位置。移动或分组不会加载聊天，也不会停止后台工作。

**快捷消息** 和 **日程** 是独立可拖动、折叠的悬浮面板。快捷消息显示员工收件人，通过原有消息功能发送，无需打开历史；每位员工的快捷消息草稿分别保存在本地。日程读取原项目的定时任务目录并可打开对应设置，没有任务或功能不可用时会如实提示。

默认背景为内置浅灰渐变。在画布工具栏点 **壁纸 → 选择本地图片**，即可换成电脑里的图片。支持不超过 25 MB 的 JPEG、PNG、WebP 和 AVIF。图片铺满工作区，并使用轻微遮罩保证可读性。图片缩放后只保存在当前浏览器或应用配置中，不会上传，也不调用图片生成 API。**恢复默认背景** 会删除保存的图片，回到渐变背景。选择或保存失败会保留原有壁纸。

创建员工和头像设置新增七款内置 Starbots 角色头像：总助理、技术、设计、行政、运营、财务、销售。已有头像保持不变，仍可上传图片或选择原有 Bot 形象。选择角色头像只更换图片，不会更改员工职责、模型或权限。

桌面采用固定视口：拖动员工入口和浮动组件排列，或在空白处按住右键框选员工；不提供背景平移和滚轮缩放。**窗口分组** 整理窗口，其名称可以修改；选中员工或从视觉分组点 **创建群聊**，会在原有建群表单里预选成员，选择管理员并确认后才建立真正的群聊。群聊卡片可查看管理员、回复模式、成员头像及工作状态，并直接打开群设置。员工头像保留详情和原有管理菜单，选中两位员工还可查看双方的协作消息。画布没有手工连线或工作流操作。点工具栏的 **经典视图** 回到原来的对话界面和侧栏，再从侧边栏的 **员工画布** 返回。布局、面板位置、快捷消息草稿和视图偏好只保存在当前浏览器，不会同步到其他设备。

员工协作群还支持类似桌面的操作：

- 将两个员工的头像重叠，确认后建立协作群。
- 在画布空白处右键，选择 **新建空白群组**，也可使用工具栏按钮。拖动标题移动群组，双击名称重命名。
- 按住鼠标右键拖动，框选多个员工；再右键画布空白处选择建群，或拖动任意一个已选头像，将整组选中成员加入空白群组或已有协作群。右键头像打开该员工的管理菜单。
- 把单个员工（也支持从员工目录拖出）拖到协作群卡片上，即可确认入群。确认框列出待加入成员，已有成员不会重复添加。

空白群组和只有一名成员的群组是本地草稿，随画布布局保存；第二名员工加入并确认后才建立真实群聊。草稿不会发送消息。取消头像拖入会恢复原位置，请求失败可以重试。这些操作不会改变员工归属、合并私聊，也不会改变正在执行的任务或权限。普通群聊和视觉窗口分组保持各自原有的操作方式。

### Bot

你可以在一个窗口中和一个 bot 完成所有对话和工作，你无需担心背后的上下文问题。你可以在 bot 详情页查看 bot 信息，也可以为 bot 选择你想使用的模型。你可以随时切换模型，但我仍然建议你为一个 bot 长期保持一个模型，仅在真正必要的时刻切换。

另外，bot 拥有记忆，它会记住你的喜好并在下次的工作中应用。你可以在 bot 的详情页管理记忆，也可以直接和 bot 对话来进行管理。

![bot 详情页：模型、记忆、用量](docs/images/details.zh.png)

### Main bot

这个 bot 作为你的 chief，它拥有非常高的权限，可以管理其他 bot 和群聊。第一次进入 ds bot 时，默认会有一个 main bot 叫 Chief。你可以直接和它对话，让它引导你完成配置。

总之，有问题，找 main bot。

### 群聊

ds bot 拥有群聊功能。群聊是非常好的多 bot 协作方式，但它会带来非常明显的费用问题。ds bot 为此特意做了优化：在一个群聊中，你需要设置一个管理员。你的消息默认由管理员回复，它会帮你调用其他 bot。你也可以直接 @ 你需要沟通的 bot，它会直接回应你：输入 @，从列表里选 bot 就行。想让 bot 参考另一段对话，点输入框的 + → 引用对话。

任何 bot 都可以用 @ 把活派给另一个 bot。接活的 bot 自己去做，群聊照常进行。它干活时，群聊、侧边栏和它自己的聊天里都能看到它在做什么。做完后，它把结果发到群里，由派活的 bot 接着回应。要停下它的工作，打开群聊详情。

![群聊：管理员 Chief 把活派给写手和程序员](docs/images/group.zh.png)

### 能力

设置 → **能力** 是团队共享的 MCP 服务、技能和能力包列表。在 Bot 设置中启用能力后，从该 Bot 下一条消息开始生效，也适用于它参与的群聊。Bot 添加的本地 MCP 命令需要你先批准才能运行。有其他 Bot 在用的能力，只有你或主 Bot 能修改、删除。

### 用量

在 设置 → 用量 里，可以按时间、按 bot、按模型查看 Token 用量。

![用量页](docs/images/usage.zh.png)

## 数据

员工、群聊和对话数据都在你自己的电脑上，在 dsh 主目录（默认 `~/.dsh`）的 `bot/` 和 `sessions/` 里。卸载插件不会删除这些数据。画布布局和所选壁纸单独保存在浏览器本地；清除浏览器存储会重置布局并移除壁纸，但不会删除员工或对话。

### 群聊逐步回复

群聊展示员工实际生成的回复，当前员工结束后才轮到下一位；执行工具时不再因超过 15 秒而提前跳过。包含至少两位员工有效回复的任务类讨论，结束时由群管理员汇总一次；普通闲聊不额外总结。已有任务占用、权限等待或长时间无响应时保留状态提示与后续回报。

### 按任务管理执行上下文

长期员工与总助理在任务明确完成后进入新的对话分段，旧记录仍可查询。每个群拥有独立的员工执行会话，群内派工保留在对应群。总助成功交接任务后释放其私聊任务上下文；群内产出保留在群里，任务索引按需查询。可复用经验独立提炼到有限容量的记忆主题，不自动注入全部任务结果。临时员工仅在没有其他工作、问题、审批、排队消息或定时任务时退场，历史身份和产物保留。参见[实现说明](docs/qibitai-task-context-lifecycle.zh.md)。
