## 报错后的操作

1. 员工模型调用报错后，私聊或对应群聊显示恢复卡片，展示错误类别和处理建议。
2. “重试未完成的任务”向原会话发送一次恢复请求，要求参考已有记录、只继续未完成工作、沿用原任务范围和授权。不会清空历史，也不会发起无限重试循环。
3. “请总助排查”由用户点击触发，在总助私聊中提供错误代码等诊断信息。团队栏内点击会在同一个聊天面板切换到总助。
4. 总助回复后显示查看建议入口，不把诊断回复等同于原问题已修好。原会话成功完成一轮后才清除其失败记录。
5. 总助调用失败、排查投递失败或排查被重启打断时，由软件显示本地提示。排查超过 90 秒仍未结束时，提示检查总助对话和模型连接，不重复提交排查。
6. 提供“检查模型配置”和“复制错误信息”，便于用户自行处理或向支持人员反馈。

## 边界

- 恢复操作拒绝过期错误、旧会话分段、忙碌中的会话、进行中的群聊轮次以及短时间重复点击。
- 总助收到的是排查建议任务，提示词要求不修改配置、不重试原任务。此约束不等同于独立的只读工具沙箱。
- 密钥无效、账户余额不足及供应商故障仍需要用户或服务商处理，不能保证总助自动修好。
- 重试通过模型理解原历史继续任务，不是事务回滚，也不是对外部副作用的严格幂等保证；恢复提示词明确禁止重复已完成的副作用。
- 新增失败记录最多保存 50 条，保存代码、身份、时间、次数和排查状态，不复制原始提示词、密钥或供应商报错正文。
- 诊断中列出的是员工配置的默认模型，不代表任务路由临时选用的模型一定相同。
- 本地提醒不依赖总助生成回复，但需要桌面应用及插件后端正常运行。
