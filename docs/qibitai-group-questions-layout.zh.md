# 群内问答与布局修复（插件 0.1.41）

## 问题与修复

1. 新群输入框靠顶部：团队栏位于画布容器外，未命中画布的底部布局规则。为共享聊天容器补齐弹性高度、底部吸附与自动间距，空会话和长会话均使用同一规则。
2. 建群顺序与提问主体：原工具明确禁止群成员使用 `ask_user`，导致需求由总助转问。现支持群内成员各自的非阻塞问题卡片；先判断协作需求、建群，再让负责人直接问其职责范围的问题。新建任务群当轮不允许创建人在私聊继续发问题卡。
3. 回答路径：用户选择卡片后，答案保留在群聊记录中，由对应员工的群会话继续处理；不交给 Chief 代转。同轮多个答案均保留目标员工。只有一个待答问题时可直接在输入框回答；多个问题时用对应卡片或 @负责人，避免猜测答案归属。
4. 点击工作状态：原先调用打开设置，现打开执行过程窗口，按需轮询实际工具步骤及模型返回的 reasoning。未返回文字则明确显示暂无；失败或放弃的流式尝试清除。工具参数、密钥不进入该接口；保留最近 30 个工具事件和最多 16,000 字符 reasoning。进度为当前进程内信息，重启不恢复历史细节。
5. 群头像：位于第一条气泡顶部，后续气泡保持同一缩进。
6. 工作状态行：后台任务、当前发言的来源不同，但不代表应采用不同对齐；统一左对齐，当前发言从群内状态读取，避免错误拿到员工私聊工具状态。

## 可靠性

- 每位员工独立问题，持久化保存；待答问题阻止任务完成或自动总结。
- 卡片答案先领取，拒绝重复回答；提交异常恢复问题。
- 员工离群后取消问题，旧答案不再投递。
- 群问题键盘快捷键一次只回答第一张，避免一次按键回答多名员工。
- 不改团队归属、权限、私聊记忆及任务模型规则。领域需求收集阶段使用群内发言，正式任务仍使用已有模型分配流程。
- 协作判定由模型遵循提示规则，不能宣称所有真实模型都必然按理想顺序决策；已建群当轮的私聊卡片有代码级拦截。

## 验证

- mock 单元测试：两人提问、定向回答、重复提交、自由文本回答、重启后问题恢复、离群拒绝、执行步骤与 reasoning、放弃流清除。
- 隔离浏览器验证：空群输入框位置、群内卡片作答、原员工接答、执行窗口不进设置、头像顶部、画布弹窗。
- 真实桌面部署仅更新 ds-bot 插件；使用 mock 模型测试，不消耗用户真实模型额度。
