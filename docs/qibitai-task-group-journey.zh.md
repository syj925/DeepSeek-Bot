# QibitAI 任务群协作流程（插件 0.1.39）

## 使用方式

向总助或主管提出需要多人共同交付的任务。负责人通过 `create_group.task_objective` 创建任务群，并通过 `post_to_group` 下发任务。创建结果在原聊天记录中显示员工卡片，用户可选择“进入协作”或“留在这里看进度”。不自动抢走正在输入的对话。

任务群顶部提供返回负责人的入口。团队栏在原区域切换；桌面聊天弹窗在同一个窗口切换，保留窗口尺寸、位置和会话草稿。普通聊天群保持原行为。

只有群负责人声明 `complete_task`、成功结束回复，并且整轮没有待发言、后台工作、未回收的委派、授权请求、提问或模型错误时，任务群才归档。单轮结束不代表任务结束。结果与完成通知保留，并向创建者发送汇报；汇报连接失败时保留结果卡并提示，不自动无限重试。

已完成任务从常规团队列表收起，保留在创建者对话的“已完成任务”折叠区。进入后可查看历史和继续原任务。用户发送补充要求，或负责人再次向原群下发任务，恢复原群并增加任务轮次。不会删除员工、改变团队归属或权限。

## 组群边界

- 普通问题、单人独立委派：沿用私聊。
- 多人相互依赖、共同交付：创建任务群。
- 大量互相独立的检查：沿用队列，不要求建多人群。
- 原任务修订：复用原群。相同创建者、相同目标的重复创建复用已有群。

## 状态与边界

状态存在插件自身 `state.json` 的 `room.task`，不更改 Harness。字段包含目标、创建者、active/completed、任务轮次和最终交付摘要。未结束轮次的完成声明在重启后清除，避免误归档。员工状态来自实际群轮次和后台任务，不使用模拟进度。

完成判断仍需要模型执行完成工具；软件不能仅凭自然语言判断所有业务成果是否正确。旧群不自动迁移为任务群。归档不等于删除，不清除用户历史。图片角色 Skill 是独立需求，未包含在本次改动中。

## 验证

- 773 项单元测试通过，包含归档、继续原群、阻塞、普通群兼容、汇报失败和幂等。
- 客户端构建一致性检查通过；lint 无错误，存在仓库原有警告。
- 独立 mock 环境 40 步原有功能冒烟测试通过。
- Chromium 联调通过：创建群→原聊天卡片→进入协作→返回→草稿保留→显式完成→折叠归档→汇报→补充要求恢复原群→桌面弹窗内往返。
- 使用模拟模型，不消耗真实付费模型。以上不代表真实模型业务质量已经验证。
