# 任务上下文与员工记忆

适用项目：DeepSeek-Bot / QibitAI 画布员工系统。2026-10-19。

## 已实现的行为

| 对象 | 执行时 | 完成后 | 再次使用 |
| --- | --- | --- | --- |
| 总助理 | 私聊接需求；共享交付转入任务群 | 成功交接后释放本次私聊上下文；群结果保存为索引，不自动回传完整报告 | 按需查询任务索引、旧聊天；用户偏好仍由原记忆机制保存 |
| 长期员工、主管 | 私聊和每个群各有独立执行会话 | 明确完成并成功结束后转为新分段；旧分段可查，默认不重复注入 | 保留身份、角色、能力、模型默认值和权限；按需检索经验和结果 |
| 临时员工 | 仅保存任务所需上下文；不写长期记忆 | 无其他工作后退出在职列表、归档执行会话 | 不再接受派工；需要继续时安排在职员工或创建新临时员工 |
| 任务群 | 要求、问答、执行与产物保留在群里 | 保留群、聊天、文件路径及结果；分别释放成员执行上下文 | 追问重新激活原群，携带简短的上一轮结果，旧执行细节按需读取 |

临时员工采用逻辑退场，不物理删除历史身份和产物。存在其他活跃群、普通群、私聊工作、排队消息、待回答问题、审批、未回传委托或定时任务时延后退场。长期部门成员或主管须先使用长期身份。

## 什么算完成

不是每条回复结束就清理。普通聊天、进度、内部汇报和失败回复均不触发。

私聊：员工调用 complete_task，成功完成最终回复，且没有问题、审批等阻塞。
任务群：协调者调用 complete_task；本轮结束后确认员工贡献已返回、没有未完成委托、失败、排队群消息、问题或审批。
总助交接：成功 post_to_group 后，当前总助回复成功结束，才申请释放其私聊上下文。后续用户新消息优先，取消过期的清理请求。

## 上下文隔离

员工 A 的私聊、群 X、群 Y 分别对应执行 Session。群内 message_bot 派工到收件人在同一群的执行 Session，不再进入其私聊。未入群的收件人必须先加入；明确 reply_to=user 仍表示用户要求转到私聊。

新群不自动复制员工的近期私聊。用户界面不需要为每个任务手工建额外窗口。单个私聊仍按顺序处理，不自动推断同一段私聊中的多个独立目标；未明确完成的任务继续保留上下文。

## 结果与经验分开

- 任务索引：按员工保存在本机状态数据，包含标题、简短结果、群/会话定位、时间和文件路径。read_task_history 可搜索并分页；不把全部任务索引塞入系统提示词。
- 可复用经验：完成后后台提炼最多 3 条、每条最多 300 字符，经现有记忆校验、去重和敏感内容过滤后，进入该员工的 task-lessons 主题。默认上下文只看到主题入口，使用 recall 按需读取。
- 原有用户偏好、决策和组织信息仍由原记忆机制维护。任务提炼不能把产出全文当经验，也不能凭任务证据创造用户偏好。
- 经验提炼会产生额外模型调用，使用现有记忆调用路径；失败最多尝试 3 轮，不阻止交付，不无限重试。关闭 memory 时不运行提炼。
- 经验不保证每项任务都有。无复用价值可返回空列表，原始记录仍保存。主题达到已有容量上限后写入失败，需通过现有记忆管理整理。

read_own_chat 查询私聊历史；read_group_chat 默认看近期共享消息，part 参数可查看本人在该群的旧执行分段，query 可筛选。完整共享聊天仍由宿主历史保存，当前接口不提供整个群的无限全文检索。

## 安全边界与恢复

上下文切换复用宿主公开 API 和插件已有的分段机制；不修改宿主内核，不强制终止工作。完成切换使用独立原因，不走错误/溢出重试，不重新启动已完成任务。切换过程中到达的输入交给新分段。

清理标记保存在状态文件；每 15 秒尝试安全处理。归档失败保留 archivePending，下次重试。临时员工归档不传 stopActivity，不强行停止其他工作。已有默认模型、模型能力、权限和文件目录机制继续沿用，任务结束不会提升权限或删除交付文件。

旧用户数据不做批量清理，已有员工迁移为长期员工；只有之后明确完成或成功交接的任务触发新流程。
