# 0.1.62 主干合并说明

本轮以 `main` 的 `4370d83` 为基础，合入 `feat/qibitai-main-agent-groups` 的 `ced3ac3`，保留双方提交历史。版本统一为 0.1.62，`main` 继续作为开发与 HTTPS 发布底座。

## 接入的协作界面

- 部门 Dock、总裁办与临时员工集合、设置和换肤入口，均基于实际员工和部门数据。
- 当前对话拖出画布：复用原会话、草稿及消息，支持已有窗口重定位、键盘操作和手势取消。
- 协作记录覆盖来源聊天，按时间更新；上翻时保留位置，加载失败保留已有记录，关闭后恢复焦点。
- 已完成任务结果卡、团队联系人排序、桌面组件移除和恢复。
- 开启 `presetOrganization` 后一次性初始化预置组织，补齐缺少的预设部门与员工；已有同名部门保留，已完成初始化不会重建后来删除的员工。

## 保留的主干行为

- 群成员逐段回复、字符渐显、模型返回的思考内容展示、阅读历史时停止跟随。
- 固定输入框、输入反馈、厂商图标与成员模型选择、@补全及点名交互。
- 用户明确要求时才能更换员工模型；已有管理权限和删除员工规则继续生效。
- 工具检查、实际执行会话的原生浏览器入口、员工群工作动态与原有上下文归属。
- 原有 ASCII 素材路径、稳定更新源、测试矩阵及 HTTPS 发布流水线。

Windows 状态文件原子替换遇到短暂占用时，会进行有限重试；每次重试前重验写入所有权。权限已转交给其他宿主或重试失败时，不删除已保存的数据文件。

## 后续协作

后续从最新 `main` 创建或更新开发分支。已合并分支的工作副本可先获取远端，再将本地开发分支快进到远端 `main`；若本地还有额外提交，先保留改动再正常合并，不强推、不以旧源码包整目录覆盖。

`ds-bot/client.js` 仍由 `src/client` 构建生成。发布标签必须为 `ds-bot-v<package.json 版本>` 且指向 `main` 历史；[发布流程](plugin-release.md) 继续适用。浏览器 UI 实测与 API/组件测试应分别记录，本轮自动浏览器访问被权限门禁拒绝，不能据此宣称真实桌面交互已验收。
