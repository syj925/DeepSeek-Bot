## 如何接手

先读根目录 `AGENTS.md`、`UI-HANDOFF.md` 和本文件，从交付提交创建独立 UI 分支。设计师负责视觉和交互方案，功能侧接入确认后的设计；接手 AI 不自行改换整体风格。修改真实组件并保留现有 actions、订阅、身份标识和错误处理；需要新数据时列出接口需求，不用演示数据替代业务接口。

修改 `ds-bot/src/client/` 后重新生成 `ds-bot/client.js`，两者一起回传。不要直接改生成文件，不修改 Harness、正式安装目录或用户数据。旧源码包仅作参考，不能覆盖本版。

### 会话显示与组织关系分开

`hidden` 是会话列表偏好，不表示删除、离职或退出部门。部门成员关系来自 `roster.teams`、员工归属及在职状态，不从当前显示的聊天列表反推。

只有用户主动打开聊天才调用 `restoreEmployeeConversation`，通过现有 `set-flags` 保存该员工的 `hidden: false`。悬停、选中图标、拖动、放到画布、窗口挂载和恢复布局都不能解除隐藏。跨会话分段使用稳定员工 ID；重复打开合并保存请求，失败提示，等待下次明确操作，不自动循环重试。

### 拖拽坐标与菜单浮层

`updateCanvas` 会经过 `fixedDesktop`，可能把首次拖出的图标校正到桌面边界内。临时移动必须以 DOM 实际渲染的 `left/top` 为起点，不能继续减去未经校正的原始快照坐标。`paintCanvasDrag` 在首次挂载及后续移动时统一绘制；首次节点还没出现时不能永久缓存空列表。拖动中只更新目标节点的临时 transform，松手提交正式位置并清理 transform，避免每帧发布整个画布状态。

绿色框是松手后的吸附位置，头像在拖动时跟随鼠标，两者不要求始终重合。不要为了让它们重合而取消原有空间避让或吸附规则。

成员菜单使用既有全局浮层，不能嵌在成员列表的滚动裁切区域内。边界计算使用未被入场缩放动画影响的尺寸，保留点击外部／Escape 关闭、取消确认、键盘焦点和中英文文案。

## 信息栏与任务能力继续保留

| 分类 | 内容与边界 |
| --- | --- |
| 任务 | 历史任务、相关协作。保留任务状态、检查点、验收与成果版本；相关协作是对应群聊的跳转入口。 |
| 成果 | 产出文件、岗位经验。文件保留图标、名称、来源和打开入口；员工信息栏直接对应当前员工，无需另选所属员工。经验可编辑，来源用「来源：任务名 · 员工名」，只展示已保存的依据。 |
| 待处理 | 任务问题、授权、工具／环境问题和错误恢复。显示真实阻塞及恢复操作；折叠不等于问题已解决。 |

- 各分区可收起，同一会话的团队栏和弹窗共享本机偏好；收起时保留正在编辑的经验草稿。
- 不可用文件默认折叠，可重新检查或移除列表记录，并提供撤销。移除不删除磁盘文件、任务历史或归档交付；记录恢复可用或重新交付后可再次显示。
- 普通问答保留员工会话；独立任务只关联实际参与者与必要对话。私聊任务验收后重置执行上下文，保留历史与经验；不把全部历史任务重新注入新任务。
- 明确的新任务／续做按意图处理，模糊输入在输入框旁询问并保留消息和附件。不能将确认入口藏入深层历史菜单。
- 完成文件不等于通过业务验收，模型不能替用户验收。继续、返工、重试、授权、查看分别走现有接口。
- “已处理”保留诊断并收起提醒，不重复执行任务。同一会话后续有效回复可清理旧模型错误，其他员工的诊断不算原员工恢复。

更完整的任务与信息栏基线见 [0.1.82 交接](UI-HANDOFF-0.1.82.zh.md)、[独立任务接口](independent-tasks-mvp.zh.md) 和 [上下文隔离](task-context-isolation.zh.md)。本轮未更改 Host 的任务、记忆或权限规则。

## 测试与回传

在 `ds-bot/` 运行：

```sh
npm ci
npm run harness
npm run build
npm test
node scripts/build-client.mjs --check
npm run lint
```

本版 1,312 项单元测试、构建一致性和 lint 通过。已有 lint 警告未新增；首次全量运行与浏览器并行时，一项记忆摘要测试的固定 20ms 等待未完成，未修改源码的完整复跑已通过。Host 未变化；将来若改 Host，另需独立 `.dsh-test-*` 与 mock 模型冒烟检查。

界面验收至少覆盖：

1. 隐藏部门员工会话后，Dock 部门及其成员仍可用；悬停、拖动不会恢复其他隐藏会话。
2. 主动打开一位隐藏员工，再切到 Chief、关闭聊天、重启，只有该员工恢复；再次隐藏可生效。
3. 菜单在滚动列表、小窗口和屏幕边缘不被裁切；删除确认可取消，保护原因准确，重复点击不重复提交。
4. 600／900／1280px 窗口和 100%／125%／150% 显示缩放下，新图标和已有图标都跟随鼠标；松手按预览落点，取消不遗留网格或移除提示。
5. 部门成员卡片拖出、建群／入群、信息栏三分类、编辑草稿及多窗口同步仍能工作。

交付前的拖拽、菜单和删除交互使用隔离虚拟员工验证；正式桌面只核对加载状态、接口和文件一致性，未删除真实员工或发送消息。不要用正式数据做删除测试。

回传：基准提交、UI 分支或补丁、逐文件变更说明、截图／录屏、测试结果和未解决问题。必须包含生成后的 `client.js`；不包含依赖、用户会话、密钥、浏览器个人配置或本机安装备份。
