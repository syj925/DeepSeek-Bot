# 新任务上下文隔离（Bot 0.1.80）

## 用户操作

- 私聊明确说“新任务：……”时，自动创建新的执行会话，不携带前一任务的消息、摘要和要求。原任务仍可查看，未完成任务保存进度并暂停。明确说“继续当前任务”“把这份报告……”等续做指令时，保持当前上下文。
- 已登记任务中遇到无法确定边界的输入时，先保留消息及附件，在聊天输入框旁询问“继续当前任务／开始新任务”。选择后才执行，切换失败或重启后仍保留待发送内容，不自动重复派发。没有独立任务记录的普通聊天不逐条询问。
- 历史任务 → **继续**：只继续所选任务。若它已离开当前会话，先创建独立上下文，再关联该任务，按其检查点继续。另一任务尚在当前上下文中时会拒绝抢占。
- 私聊独立任务 → **验收**：保存验收及文件版本后重置执行上下文。若重置失败，验收结果仍保留，允许同步重试；下一次用户输入在读取旧上下文前也会检查此边界。
- 普通点击联系人仍然打开原会话；新建会话面板选择已有员工时才执行新任务隔离。

正在执行、待回答问题、待授权、待员工回复时不允许主动切换。切换使用当前会话标识校验，旧页面不能误重置一个更新的会话；创建期间到达的新工作也会使主动切换停止。

## 保存与读取

历史任务、原对话分段、文件交付版本和岗位经验都保留。新上下文的默认提示不再注入个人及团队 MEMORY.md 的完整内容；相关经验通过 `recall` 的具体关键词读取，最多返回五条，忽略经验来源元数据里的旧任务长摘要。历史任务工具要求检索条件，任务记录工具省略任务 ID 时仅返回当前绑定的任务。

员工角色、用户配置的岗位指令、工具权限和当前工作目录仍然有效。隔离不是删除存档，也不是禁止员工在用户需要时读取资料；用户明确继续或查询旧任务时，对应记录仍可读取。岗位经验继续支持编辑与来源追溯。

## 实现范围

全部修改在 DS Bot 插件内，使用 DSH 公开的会话与工具接口。没有修改 Harness 执行器、开发版或另建第二套任务调度器。已有未完成私聊不会在升级时被强行清空；明确开始新任务、选择新任务、验收或 `/clear` 建立干净边界后持续使用隔离的记忆读取策略。`/clear` 清理消息但保留未完成任务的关联，不能替代新任务操作。

边界识别采用本地明确意图规则，不增加模型请求。它不宣称能理解所有话题变化；模糊的新目标由用户确认，避免误清正在进行的工作。消息正在执行、任务选择待处理或有未完成委派时，验收及切换会阻止抢占。

任务验收只表示用户认可所选成果，不把任意任务摘要自动变成已确认业务规则；原有岗位经验与记忆审核功能保留。对于新任务需要的公司知识，员工应根据本轮请求检索，不能把旧客户、旧日期、旧筛选条件默认为本轮要求。

## 提醒与界面

信息栏仍分为任务、成果、待处理：历史任务与相关群聊在任务栏，产出文件与可编辑岗位经验在成果栏，错误与恢复操作在待处理栏。任务边界询问位于聊天输入框附近，不合并成一个长面板。

“标记已处理”只收起该条提醒，保留诊断记录，不重试任务。后续同一私聊或同一员工在同一群聊中成功回复，可清理本轮开始前的模型错误；空回复、仅转交任务、总助诊断其他员工的错误，以及执行环境故障不会被误判成恢复。岗位经验的编辑与更多按钮使用统一尺寸的图标，在窄窗下保持对齐。

## 验证入口

- `npm test`、`node scripts/build-client.mjs --check`、`npm run lint`。
- `dev/task-isolation-smoke.mjs`：隔离的真实 Host 和本地 mock 模型，检查实际模型请求中的旧内容标记，验证新任务、定向经验检索、继续指定任务、私聊验收、成果文件与重启。
- `dev/work-tasks-smoke.mjs`：原有独立任务、群聊、交付验收与版本保留回归。

所有测试使用独立 `.dsh-test-*` 数据，不向用户桌面的员工发送测试任务。
