# 画布聊天输入失效与恢复入口修复

日期：2026-10-19；插件版本：0.1.37。

## 复现与原因

在团队栏打开员工会话后点击“放到画布”，输入框看起来可以打字，但占位文字仍显示，Enter 不发送。隔离 mock 环境确认：旧团队聊天保留 240ms 关闭动画，新弹窗同时挂载同一 Session；两者争用同一个 Harness 编辑器，旧窗口卸载时将新窗口使用的编辑器解绑。浏览器原生 contenteditable 仍能输入，但草稿状态、占位提示、发送按钮不再同步。

## 修复

- 插件内按 Session 协调聊天表面，同一 Session 只挂载一个可编辑会话。
- 新窗口接管前先卸载旧窗口内容，再绑定原编辑器，保留共享草稿和附件；不同员工的窗口仍可并存。
- 同一会话在另一个窗口已打开时提供“在此继续对话”；关闭当前窗口会恢复上一窗口。未修改 Harness 或 app.asar。
- 移除排查阶段的 DOM 占位隐藏与 Enter 代点补丁，使用恢复后的原生编辑器处理 Enter、Shift+Enter、中文输入法和发送。
- 报错恢复按员工身份跨分段关联，同时显示在总助排查会话；补上首次加载、排查中断的本地提醒，状态不变时不反复弹出。
- 恢复卡片只针对未恢复的错误，后续会话成功完成会清除。旧聊天中历史红色错误不等于当前仍需恢复；总助自身失败时不会提供向自己发起排查的按钮。

## 验证

- 765 项测试通过，构建一致性检查通过，lint 无错误（既有警告保留）。
- 隔离浏览器实测：团队草稿转入弹窗、占位消失、Enter 发送、Shift+Enter 换行、输入法确认不发送、返回团队聊天、关闭后恢复弹窗输入。
- 模拟模型端到端：员工报错、四个恢复入口、总助诊断、手动重试成功清除、总助失败本地提醒通过；90 秒超时状态及通知去重由可控时钟/状态测试验证。
- 未调用用户付费模型，未测试或清理真实会话数据。
