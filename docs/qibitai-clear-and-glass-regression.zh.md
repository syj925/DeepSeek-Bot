# QibitAI 上下文清理与毛玻璃聊天框回归

## 问题

- `/clear` 原先只是普通文本，模型可以回复“已清空”，但实际会话和上下文没有切换。
- 聊天弹窗和输入区曾使用固定的近不透明浅灰/白色，在不同壁纸上会盖住毛玻璃效果，产生突兀的白色矩形。

## 处理

- 只识别用户单独发送的 `/clear`，不把它交给模型；清理通过新的会话分段完成，旧消息仍可从历史中查看。
- 清理时保留角色基础说明、工具定义和长期记忆，因此上下文指标会保留基础占用，不承诺归零。
- 有未完成审批、问题卡、委托或正在执行的中途步骤时，清理会给出本地提示，避免丢失工作；附件与 `/clear` 混发也会拒绝。
- 聊天窗口、输入座位和输入卡片改为使用 `--glass-window`、`--glass-floating`、`--glass-border`、`--glass-blur` 等主题变量，跟随壁纸和主题变化；仅在系统要求降低透明度时使用不透明回退。

## 验证

- 单元测试：797 项通过。
- 隔离 mock 桌面：`/clear` 不产生模型调用，下一次请求使用新的会话分段；UI 指示显示“上下文已清理 · 历史记录保留”，新请求的上下文指标从旧值降到基础占用。
- 输入区计算样式为透明座位，输入卡片使用主题玻璃变量；无页面错误。
