# 员工、团队与协作群

本次调整用于 Bot 插件 0.1.21，不修改 QibitAI 主程序或 dev 源码。

## 用户操作

员工是持续存在的工作身份，有独立模型、会话和记忆。创建员工时默认独立，也可选择已有团队；在员工设置中可以显式调整归属。用户无需先选主 Agent 或子 Agent。原有管理权限仍单独保留。

团队是长期组织，必须有名称、职责、负责人和固定成员。每位员工最多归属一个长期团队，可以加入多个协作群。Chief 是唯一总助，不属于部门，也不能复制或创建另一位总助。

可以向 Chief 说：“建立市场团队，由负责人协调调研和文案两名员工。”如已有员工，可以说：“用现有的研究员和写手组成内容团队，由写手负责，长期负责公众号内容。”前者使用 `create_department`，后者使用 `organize_team`。转组使用 `assign_employee`，需要明确的用户意图。

协作群用于聊天和任务协作，可以跨团队，也可以包含独立员工。头像重叠建群、框选建群、拖入空白群或已有群均支持所有员工。退出或删除群不会解散团队，画布视觉分组也不代表组织归属。默认由群协调者先回复，`@姓名` 可指定成员。

跨团队任务直接发送给目标员工，不需要负责人转发。负责人协调分工、进度和成果。忙碌员工接到新任务默认排队，显式 `when: now` 用于纠正或紧急补充。原有消息跳数、未读数量和群回复循环限制继续生效。

## 数据与权限

组织记录保存在 `state.teams`，员工用 `teamId` 标记归属；`createdBy` 只保留创建历史。聊天群仍独立存储，不根据群成员推断团队。

旧版明确通过总助创建的部门只迁移一次，普通聊天群不会自动成为团队。解散团队后重启不会再次建立它。员工的会话、模型、记忆和文件权限不因建群或转组自动改变。

负责人离队或删除前必须先交接。组织负责人和原有员工管理权限分开：仅指定负责人不会自动授予管理权、完全访问或其他文件权限。
