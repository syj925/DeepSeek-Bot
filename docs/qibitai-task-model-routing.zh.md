# QibitAI 任务开始前自动选模（0.1.32）

本次基于 0.1.31 增量加入后端能力，不改变设计师的画布、头像和聊天窗口，不恢复聊天模型下拉框。

## 用户怎样使用

向总助理或主管描述目标即可。主管先拆分员工任务，通过 `message_bot` 下发时，系统在入队前选择模型。主管收到实际分配结果后，用用户的语言简短解释员工、模型和用途。用户可以在自然语言中指定模型、速度优先、费用优先或质量优先。

例如：“请安排员工整理这份资料、分析数据并写报告，简单整理速度优先，分析质量优先。”

用户明确指定模型时，主管应调用 `list_models` 确认完整标识，并传入 `model`。错误或不可用的标识会让派发失败，不会悄悄替换为其他模型。目录可用并不保证远端账户额度或权限有效；实际请求失败沿用原有错误反馈，不自动切换收费模型。

## 已实现的流程

1. `message_bot` 新增 `task_kind`（通用、写作、代码、分析、图片理解）、`priority`、`model`、`model_reason`。
2. 总助理/主管发送新任务时自动选模。未提供任务类别时，按本次消息识别，不单凭员工职位。
3. 图片理解只选择提供商明确声明支持图片输入的模型。这里只选模，不新增图片附件传输或生图能力。
4. 已配置目录中的明确模型优先；否则按透明规则匹配：轻量任务偏向轻量型号，代码偏向代码型号，分析偏向推理型号，同等情况优先员工默认型号。
5. 每次派发把模型、类型、优先级和原因保存在消息来源及交换记录中。排队、重启恢复、分段续接和工具文本重试保留该选择。
6. 用公开 `agent/pre-step` / `agent/request` 接口在准备适配器和上下文之前应用任务模型。不会调用永久设置接口，不修改员工默认模型或全局默认模型。
7. 同一员工的不同会话分别隔离，同一任务后续步骤保持模型不变。`when: now` 用于补充/纠正，不能切换模型。下一次普通聊天恢复员工默认模型。
8. 群里的普通 @ 是讨论，仍使用各员工默认模型；正式派工使用 `message_bot`，结果回到派工主管的群会话。提示词明确区分两条路径。

## 能力边界

- 当前模型目录没有统一实时价格、延迟和质量测评。速度/经济/质量是名称规则偏好，不代表客观最优、最低价或必然更快。未知型号保守使用默认模型；可用模型只有一个时仍使用它。
- 不额外调用一个模型来做选模，避免多一次延迟和付费请求。
- 用户自然语言由主管模型理解并转换为工具参数；服务端校验模型和能力，不能保证主管对任意含糊表达的理解都正确。
- 请求中模型变化可能使提供商缓存失效；上下文容量按任务模型检查，必要时沿用既有压缩/分段流程。
- 中断中的补充消息不会重选模型。需要换模型时应结束/停止当前任务，再作为新任务下发。
- 不扩大文件访问、管理权限或工具权限；模型路由不等于权限提升。

## 给 UI 设计师与 AI 的接口约定

此次不要求更换 UI。可选展示只读信息：`taskModel.ref`、`kind`、`priority`、`reason`、`explicit`，位置可放在派工记录或任务详情，禁止把它写回员工 `model` 设置。字段不存在表示普通聊天或旧记录，保持兼容。

未来如需真实价格和测评驱动选择，可提供版本化的模型能力/价格/延迟目录，再替换 `rankTaskModels`；不应在 UI 中写死跨提供商排名。

## 验证与回退

- 单元测试覆盖显式优先、缺失模型、图片能力过滤、并发会话、排队顺序、执行中纠正、恢复默认、拒绝步骤、重启消息来源、永久设置不变。
- `npm test`、`npm run lint`、`node scripts/build-client.mjs --check`。
- 完整隔离 mock 冒烟：`node dev/smoke.mjs <bench-name> <port>`。
- 真实 HTTP mock 路由验证：`node dev/task-model-smoke.mjs <bench-name> <port>`，覆盖自动 Flash、指定 Pro、分析 Pro、恢复默认和不可用模型不派发；不消耗真实付费模型额度。
- 回退可重新安装此前 0.1.31 插件包。未改员工默认模型，不需要回写或迁移员工配置；未处理的旧任务来源字段会被旧版忽略。
