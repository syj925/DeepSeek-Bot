# QibitAI 员工模型分配与任务模型（0.1.53）

员工长期保持自己保存的模型。任务类型、难度、速度、费用或质量偏好都不会自动换模型；只有用户明确要求切换时才改变。

## 在上级对话里怎样使用

- “把小林以后用的模型换成 DeepSeek V4 Pro。”上级先用 `list_models` 确认可用的完整标识，再调用 `update_bot({ bot: "小林", model: "提供商/模型", model_user_requested: true })`。这会保存小林的默认模型，从下一轮开始使用。
- “让小林这次用 Flash 整理资料，之后仍用原来的模型。”上级调用 `message_bot({ to: "小林", message: "整理资料", model: "提供商/Flash", model_user_requested: true })`。只影响这次任务，不改员工默认设置。
- “让小林整理资料、写代码、做分析。”未明确要求切换模型，派工时省略 `model`，使用小林已经保存的模型。

主管不会把“快一点”“便宜一点”“质量好一点”自行解释为更换模型。用户说要换却没有指定型号、名称对应多个提供商或模型不可用时，应先列出可用选项并澄清，不猜测替代型号。模型目录可用不保证远端账户额度、权限有效；调用失败沿用原有错误反馈，不自动切换其他收费模型。

## 权限和生效范围

总助理及原有管理关系中的上级，可以为自己管理的员工分配模型。长期团队负责人即使不是 Main Bot，也可以通过 `update_bot` 修改本团队直属员工的模型和思考等级；这项能力不授予修改员工角色、指令、工作目录或权限的权利。无关 Main Bot、其他团队或其他上级的员工不受影响。

模型参数必须同时携带 `model_user_requested: true`，表示上级根据用户当前明确要求操作；缺少这个标记的换模工具调用会被拒绝。标记不是权限提升，服务端仍检查调用方与目标员工的管理关系。自然语言意图由上级模型理解；服务端无法独立证明一段自然语言是否构成真实用户授权。

保存默认模型不会打断正在执行的任务，也不会在执行中途换模型。已开始的轮次和已记录任务模型的排队任务保留该选择；未记录路由的消息在下一轮读取员工保存的配置，新派发任务也使用新设置。`when: now` 是补充或纠正当前任务，不能用来更换该任务模型。

## 已实现的流程

1. `message_bot` 保留 `task_kind`（通用、写作、代码、分析、图片理解）、`priority`、`model`、`model_reason`，并增加 `model_user_requested`。类别与优先级只作任务信息，不触发自动换模。
2. 主管正式派工在入队时记录员工保存的模型；员工未保存模型时使用宿主默认模型。主管派工所选模型不可用时拒绝派发，不尝试猜选其他型号。普通同事消息不生成任务路由，在实际开始下一轮时读取员工配置。
3. 用户明确要求本次任务使用其他模型时，先解析可用模型，再记录只属于这次任务的选择。图片理解要求所选模型明确声明图片输入能力，不自动换成另一个视觉模型。
4. 排队、重启恢复、分段续接和工具文本重试保留该任务记录。用公开 `agent/pre-step` / `agent/request` 接口在准备适配器和上下文前应用，避免执行到一半切换。
5. 用户要求长期变更时走 `update_bot` 保存指定员工设置，不改主管、其他员工或宿主默认模型，也不迁移归属、私聊、群组和权限。
6. 群里的普通 @ 仍是讨论，使用各员工默认模型；正式派工使用 `message_bot`，结果回到派工上级的会话。

## 界面和兼容

沿用已有画布、头像、聊天窗口和员工详情设置。可选展示只读任务信息 `taskModel.ref`、`kind`、`priority`、`reason`、`explicit`；不能把任务专用模型写回员工 `model` 设置。字段不存在表示普通聊天或旧记录，保持兼容。

已有员工的保存模型保持原值，旧任务已经记录的模型继续随任务恢复。永久变更和临时任务使用不同工具路径，不需要新增会话层级，也不增加一次付费模型请求来选模。

普通私聊和群聊沿用既有的模型可用性兼容行为：若保存的模型暂时不再提供，执行时可依次使用上次可用的模型或宿主默认模型，但不会把这个临时结果写回员工保存的型号。这与主管正式派工的不可用模型拒绝机制不同，也不构成根据任务难度自动换模。
